# Аудит VIP Champ и устранение замечаний

Обновлено **21 октября 2026**, Asia/Seoul. Повторный аудит начат с `7c4ced1`.
Бот **@VIPchatadmin_bot** уже работает в новом LXC 138. База создана заново по
указанию владельца; исходной работающей SQLite-БД для переноса не было.
Этот отчёт заменяет устаревшее состояние «токен не задан, запуск не выполнен».

## Первоначальная переработка

| Область | Результат |
|---|---|
| Секреты и Git | `.history`, `.cosine`, env-файлы, старые БД и клиентские CSV удалены из доступной истории. CI проверяет текущие файлы и достижимые объекты. Очистка не заменяет отзыв опубликованных секретов. |
| Администрирование | Хеширование паролей, привязка к числовому Telegram ID, личные чаты, проверка полномочий и сроков сессии/кнопок. `/admin` и `/settings` равнозначны. |
| Запуск | Нет побочных действий при импорте модулей; конфигурация проверяется до запуска; блокировка БД допускает один обработчик очереди. |
| Хранение | PostgreSQL, отдельная роль, транзакции на операции, backup перед миграцией/импортом. SQLite сохранена для тестов и переноса других установок. |
| Рассылки | Постоянная очередь и результаты получателей; обработка Telegram 429; неопределённый результат не повторяется автоматически. |
| CSV | Валидация UTF-8, структуры, размера и Telegram ID до транзакции; совместимые импорт/экспорт, защита от формул. |
| Поставка | Python 3.13, зависимости с хешами, Drone и проверочный GitHub CI, контейнер без root с ограничениями ресурсов и журналов. |

Очистка Git подтверждает удаление из доступных веток и объектов. Она не удаляет
чужие клоны, сторонние резервные копии или недоступные внутренние кэши хостинга.

## Исправления повторного аудита

| Проблема | Исправление |
|---|---|
| Посторонние ID могли исчерпать общий лимит входа | Общий лимит расходуют только привязанные администраторы; индивидуальные ограничения сохраняются для всех. |
| Перевод строки при вставке пароля ломал вход | Сначала точный пароль, затем допустимый конечный CR/LF. Значимые пробелы сохранены; логин и пароль можно вводить отдельно. |
| Отправка без последнего подтверждения | Предпросмотр и одноразовое подтверждение с проверкой пользователя, сообщения, срока и ревизии полномочий. |
| `/cancel` не останавливал очередь | Он явно отменяет ввод; `/broadcast_cancel ID` отменяет оставшихся получателей задания владельца или суперадминистратора. |
| Не было отписки | `/stop` сохраняет отказ; `/start` подписывает снова. CSV сохраняет отказ и не переподписывает существующего клиента. |
| Публикация в старые адресаты без проверки | Проверка явного `POST_CHAT_IDS`, реального ID чата и прав текущего бота перед предпросмотром и подтверждением. Контактная ссылка не даёт разрешения публиковать. |
| Heartbeat не учитывал worker; зависший процесс не восстанавливался | Heartbeat зависит от polling, БД и worker. Независимый watchdog завершает зависший процесс; отдельные пределы старта и остановки. |
| Долгое ожидание БД | Пределы подключения, SQL и блокировок, TCP keepalive; явно заданные параметры сохраняются. |
| PostgreSQL без TLS | TLS включён без перезапуска. Проверено подключение TLS 1.3 с `verify-full`, IP SAN и закреплённым публичным сертификатом; приватный ключ остаётся на сервере. |
| Частичный файл выглядел успешным backup | Временный файл, timeout, проверка `pg_restore --list`/SQLite `quick_check`, атомарное переименование. |
| Нет регулярной копии на другой узел | PVE helper создаёт native dump, проверяет SHA-256 на `sapsan2`, публикует атомарно и применяет ограниченное хранение. Успех фиксируется только после удалённого подтверждения. |
| SQLite memory смешивала транзакции потоков | Сериализация на время всей транзакции; проверены конкурирующие commit/rollback. |
| Legacy-миграция принимала непригодные хеши | Проверка алгоритма и ограничений параметров; карантин без сохранения открытых паролей. |
| Сервер повторно собирал образ после CI | Экспорт CI-образа по digest, проверка revision и загрузка того же image ID при деплое. |
| Новый токен мог сломать рабочий env | Закрытый candidate env, проверка `getMe` до замены, публикация после health gate и восстановление прежней конфигурации при неуспехе. |

## Инфраструктура

Основной remote — `backup` на `git.smartsoltech.kr`, зеркало — `origin` на GitHub.
Основная ветка — `master`; только push этой ветки развёртывает приложение.
LXC 138 расположен на `192.168.50.250`, каталог `/opt/vip_champ`, 2 vCPU/2 GiB RAM.
PostgreSQL 16 — `192.168.20.2`, отдельная БД и ограниченная роль приложения.
Данные, контакты и администраторы сохраняются. Bootstrap-пароль удалён из env.

Drone хранит токен бота, SSH-параметры и отдельный registry secret с правами
`write:package`. Секреты недоступны pull requests и не передаются в argv.
Резервная копия на `sapsan2` защищает от потери узла приложения внутри кластера;
это не географически независимый или неизменяемый архив.
Регламент проверки, восстановления и обслуживания: [OPERATIONS.md](OPERATIONS.md).

## Проверка готовности

Регрессии охватывают авторизацию и отзыв полномочий, предпросмотр, повторное
подтверждение, отмену, отписку, CSV, конкуренцию, миграцию v1→v2, PostgreSQL
SQL/lock timeouts, backups, реальное завершение watchdog, CI transport и rollback.
Linux-проверки обязательны: пропуск POSIX-тестов в Windows не считается успехом.

Доказательство поставки — успешные **verify, build, export-image и deploy** для
одного SHA в [Drone](https://drone.smartsoltech.kr/trevor/vip_champ), совпадающие
`REVISION`/`IMAGE_ID`, здоровый runtime и проверка БД. Оба lock-файла проходят
аудит зависимостей. Эти проверки не доказывают отсутствия всех возможных ошибок
или уязвимостей базового образа.

Реализованы контакты, учёт подписчиков, администраторов, CSV и текстовые
рассылки/публикации. Медиакампании, расписание контента, сегментация, платежи и
личный кабинет не входят в текущую функциональность. Публикация требует заданного
владельцем адресата и прав текущего бота. Проверка `getMe` и polling сама по себе
не подтверждает получение сообщения клиентом: это проверяют отдельно на
согласованном получателе без массовой отправки пользователям. Уже отправленное
сообщение нельзя отозвать отменой очереди; неопределённые отправки не следует
вслепую возвращать в pending.
